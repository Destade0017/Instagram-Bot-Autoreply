1. Roadmap Philosophy

The project will be built incrementally.

Each phase should produce a working, testable result before the next phase begins.

The implementation must avoid unnecessary complexity and premature feature development.

Core principles

* Build one small capability at a time.
* Backend before frontend where practical.
* Do not implement future features early.
* Do not introduce dependencies without a clear requirement.
* Preserve working functionality when adding new features.
* Test each phase before moving forward.
* Keep Meta integration isolated from the core business logic.
* Keep the AI provider replaceable.
* Prefer simple solutions over premature abstraction.

5. Phase 2: AI Response Engine

Goal

Build the AI brain independently from Instagram.

This phase should not depend on Meta.

Tasks

* Define AI service interface.
* Implement initial AI provider.
* Create Peniel response-generation service.
* Create structured AI response format.
* Define system instructions.
* Define response safety rules.
* Define escalation conditions.
* Handle AI errors/timeouts.
* Validate AI output.
* Log AI processing safely.

Initial test

Provide a sample comment:

“Do you have a swimming pool?”

The backend should return a structured result similar to:

status: ANSWERABLE
response:
"Yes, we do. Peniel Apartments has a swimming pool..."
requires_human: false

For something unsupported:

“Can I get a 30% discount if I stay for three months?”

The system should return something like:

status: HUMAN_REVIEW
requires_human: true

The exact response wording should be generated by the AI based on approved information.

Expected outcome

A working AI response engine that can be tested without Instagram.

9. Phase 6: Instagram Webhook Integration

Goal

Connect the application to Instagram.

This is the first phase that depends heavily on Meta’s external API requirements.

Tasks

* Configure Meta developer application.
* Configure required Instagram account connection.
* Identify required permissions.
* Implement webhook endpoint.
* Implement webhook verification.
* Validate incoming events.
* Parse supported Instagram comment events.
* Normalize events into internal interaction records.
* Handle duplicate webhook events safely.
* Log integration failures.

Important architecture rule

Meta-specific implementation should remain isolated from the rest of the application.

Conceptually:

Meta/Instagram
      ↓
Instagram Adapter
      ↓
Internal Interaction
      ↓
Core Application

The rest of the application should not need to know the details of Meta’s webhook payload format.

Expected outcome

A real Instagram comment can enter the application and appear as an interaction.

Launch strategy

The first production mode should be:

Approval Mode

15. Development Order Rule

Antigravity must not skip ahead to later phases unless explicitly instructed.

For example:

* Do not implement Instagram before the AI engine is working.
* Do not implement automatic responses before approval mode has been tested.
* Do not add DMs before V1 comments are stable.
* Do not add WhatsApp before the core application works.
* Do not introduce n8n unless a specific requirement justifies it.
* Do not introduce microservices unless a specific requirement justifies them.

⸻

16. Phase Completion Rule

A phase is not considered complete merely because code has been written.

Each phase must have:

1. Implementation
2. Verification
3. Manual testing where appropriate
4. Error handling
5. Documentation updates where required
6. Confirmation that existing functionality still works

Only after verification should the project move to the next phase.
